# Wind Forecast Portal — UK Day-Ahead Buying Support

## Overview

This project is a wind generation forecasting and accuracy analysis portal designed to support day-ahead energy procurement decisions.

It compares wind generation forecasts with actual generation for January 2026 and presents forecast performance metrics through a web dashboard.

## Features

- Select a delivery date in January 2026.
- Compare forecast wind generation with actual wind generation.
- Calculate forecast accuracy metrics, including Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), Mean Absolute Percentage Error (MAPE), and bias.
- Review forecast errors by delivery day and forecast horizon, where supported by the implementation.
- Display an indicative 90th-percentile over-forecast measure to help assess forecast risk.
- Provide API endpoints for daily results, aggregated accuracy, application status, and data-coverage diagnostics.

## Data Sources

The application uses Elexon BMRS datasets:

- **FUELHH:** Actual generation, filtered to `fuelType = WIND`.
- **WINDFOR:** Wind generation forecasts, including delivery timestamps and forecast publication timestamps.

The analysis is limited to national-level wind generation for January 2026.

## Forecast Selection Method

For each delivery date, the application selects the latest eligible wind forecast published before the configured day-ahead decision cutoff.

**Decision-time assumption:** The implementation uses 09:00 UK local time on the day before delivery (D-1). This is an analytical assumption and should not be interpreted as confirmation of an official market gate-closure time.

Forecasts are matched with actual generation using their timestamps. Accuracy metrics are calculated using matched forecast and actual observations.

## Accuracy Metrics

- **MAE:** Average absolute difference between forecast and actual generation.
- **RMSE:** Square root of the average squared forecast error, giving greater weight to larger errors.
- **MAPE:** Average absolute percentage error, subject to the treatment of zero or near-zero actual values in the implementation.
- **Bias:** Average signed forecast error; positive values indicate overforecasting when calculated as forecast minus actual.
- **90th-percentile over-forecast:** An indicative measure of the upper tail of positive forecast errors. It is not a guaranteed hedge recommendation.

## Known Limitation

Actual generation is available at half-hourly resolution, giving 48 intervals in a complete day. The selected forecast records currently contain 24 hourly timestamps per full day. Consequently, only 24 timestamps match for a complete day.

Missing half-hourly forecast values are not interpolated or fabricated. The accuracy results should therefore be interpreted with this coverage limitation in mind. Further investigation is needed to establish whether eligible half-hourly forecast records are available from the source.

## Run Locally

### 1. Start the backend

Open a terminal and run:

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload
```

The backend should be available at:

`http://127.0.0.1:8000`

API documentation:

`http://127.0.0.1:8000/docs`

### 2. Start the frontend

Open a separate terminal and run:

```bash
cd frontend
npm install
npm run dev
```

Open the frontend URL printed in the terminal.

## API Endpoints

- `/api/health` — Application health check.
- `/api/status` — Application status information.
- `/api/day?date=2026-01-12` — Forecast and actual comparison for a selected delivery date.
- `/api/accuracy` — Aggregated forecast accuracy results.
- `/api/debug/coverage?date=2026-01-12` — Timestamp coverage diagnostics, if enabled in the running application.
